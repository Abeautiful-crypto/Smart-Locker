# Smart-Locker 需求说明（需求分析阶段产物）

依据：`docs/智能寄存柜-需求文档.txt`（V1.0）与 `prototype/智能寄存柜-新粗野主义原型.html`。
本文 distilled 出角色、主流程、状态机、边界与验收条件，作为开发、测试、验收的共同输入。

## 1. 角色与入口

| 角色 | 入口 | 核心操作 |
| --- | --- | --- |
| 终端用户 | 用户端（手机视图） | 登录、选网点、存件、支付、取件、订单、卡券、客服、个人中心 |
| 柜机现场 | 柜机端（10.1 寸触屏） | 待机、存包（选规格→扫码支付→开柜）、取包（输码→开柜） |
| 超管 | 管理后台 | 全部 11 模块：看板/网点/柜格监控/收费规则/优惠券/订单/营收/告警/员工/客服工作台 |
| 网点管理员 | 管理后台 | 仅本网点：看板/柜格监控/订单/营收/告警 |
| 客服 | 管理后台 | 仅客服工作台：会话回复、工单处理、下班开关 |

登录规则：
- 用户端：手机号+4 位验证码（演示固定 `1234`），未注册手机号自动注册；必须勾选用户协议与隐私政策。
- 后台：账号或手机号登录，登录时按账号自动判定角色（super/site_admin/service），不允许自选角色；演示账号在员工管理中维护。
- 角色变更、禁用后该员工登录态立即失效。

## 2. 主业务流程

存件：选网点/柜型(小/中/大) → 支付页（计费方式、单价、押金、24h 封顶、优惠券、支付方式）→ 支付成功 → 分配空闲柜格并开柜 → 放入物品关门 → 生成 6 位取件码与订单号 → 计时开始。
取件：输入 6 位取件码（或扫码/人脸/手机号+密码，任一校验通过即可）→ 校验 → 柜格弹开 → 取物关门 → 结算（多退少补）→ 柜格恢复空闲。
异常：柜门未弹开可"上报柜格异常"（选问题）→ 柜格标异常并从可分配池排除 → 生成告警；报修完成后恢复空闲。
客服：智能客服知识库关键词打分命中直接回答（不展示来源）；未命中且人工在岗（09:00–21:00）转人工；下班则记工单（工单号=日期+序号，状态待处理），告知次日优先处理；紧急引导拨打热线。通信通道 WebSocket → HTTP 轮询 → 本地模拟降级。

## 3. 状态机

### 3.1 柜格 locker：`idle → occupied → idle`；`idle|occupied → fault → idle`
- 分配成功即 occupied；取件关门后 idle。
- 用户上报异常或系统自检 → fault（记录来源 user_report/system_check、问题描述）。
- fault 柜格不得被分配；报修/切换柜格后恢复 idle；远程开柜不改变状态归属订单。

### 3.2 订单 order：`active → finished`
- 创建（支付成功）即 active，含柜格、规格、模式（prepaid 预付 / deposit 押金）、预付金额、押金、优惠券、开始时间、取件码。
- 取件校验通过+关门 → 结算 → finished。结算分支（订单详情五状态）：
  1. 无需补交：时长费 ≤ 已付（预付），余额+押金原路退回。
  2. 需补交（超时）：时长费 > 已付，需补差额后完成。
  3. 需退款（提前取件）：10 分钟内结束→全额退款；一般提前取件退余额。
  4. 已结束需补交 / 已结束不退不补：详情页对应展示。
- 10 分钟免费时长：寄存后 10 分钟内结束不收费、全额退款。

### 3.3 优惠券：`usable → used | expired`；后台启停开关实时控制可用性
- 券在下单时选择、结束订单时结算；8 折券=时长费×20% 减免；1 小时券抵 1 小时费用；1 元券立减 1 元；均不超过订单时长费；仅限本人、用后不恢复。

### 3.4 告警 alert：`open → handled`；级别 高/中；来源：用户上报/柜门超时未关/设备网络异常/用户开门失败。
### 3.5 工单 ticket：`pending → resolved`；客服工作台可回复并结案。

## 4. 收费规则（硬约束）

| 规格 | 按时单价 | 24h 封顶 | 按日单价 | 押金 |
| --- | --- | --- | --- | --- |
| 小 | 5 元/h | 50 元 | 5 元/日 | 10 元 |
| 中 | 7 元/h | 70 元 | 7 元/日 | 20 元 |
| 大 | 10 元/h | 100 元 | 10 元/日 | 30 元 |

- 预付金额 = 所选规格 1 小时费用 + 押金；押金模式先押金、不预付租金，结束按实际时长扣费退余额。
- 每网点仅一种收费模式（按时/按日），超管可在规则页配置三种规格单价与押金、24h 封顶、免费时长（默认 10 分钟）。

无权限菜单不展示；直接请求对应 API 返回 403；网点管理员数据范围强制限定本网点（防越权改网点 ID）。

## 6. 数据一致性要求

- 柜格状态、空闲格数、订单状态三端实时一致。
- 优惠券停用后 C 端立即不可用（下单选择与结算校验双重拦截）。
- 服务重启后订单/柜格/券/工单数据可查（MySQL 持久化）。

## 7. 验收条件（可验证）

1. 三端功能完整（用户端 8 模块/柜机端 3 页/后台 11 模块）。
2. 主流程闭环：选柜→支付→开柜→存放→取件→结算→柜格释放，费用计算准确。
3. 数据联动正确：取件后首页空闲数更新；券停用后 C 端立即可用性变化。
4. 计费准确：按时/按日、封顶、押金、10 分钟免费、多退少补。
5. 客服与工单：知识库命中不显示来源；未命中按在岗状态转人工或记工单；通道可降级。
6. 权限隔离：三角色仅见对应菜单，越权 API 403；角色变更后登录态失效。
7. 优惠券管理：新建券信息完整、同步 C 端。
8. 异常处理：上报生成告警并标异常；告警处理后数量减少；地图降级不空白。
9. 单测覆盖率 ≥85%；`go vet`/`gofmt`/`-race` 通过；CI 门禁通过。
