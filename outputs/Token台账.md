# Token 用量台账（#605，估算值）

> 说明：本环境不提供逐次调用的精确 token 计量，以下为按会话消息量级的估算，已明确标注"估算"。精确值以平台侧用量统计为准（责任：学生登录 CodeBuddy/GitHub 平台核对，本台账不编造精确数字）。

## 1. 会话构成

| 阶段 | 会话 | 主要活动 | 估算量级 |
| --- | --- | --- | --- |
| 需求分析/任务规划 | 会话 1（docs v0.1.0） | 读 PRD+原型、写分析文档与任务清单 | ~100k tokens |
| 后端开发 | 会话 2（feat v0.2.0） | 迁移/存储层/业务层/HTTP API 全量编码 | ~300k tokens |
| 测试与覆盖率 | 会话 3（test v0.2.1） | 单测/集成/错误注入、覆盖率补齐至 85%+ | ~200k tokens |
| 前端 SPA | 会话 4（feat v0.3.0 #301–303） | 原型爬取、CSS 提取、12+3+11 页复刻、e2e 调试 | ~300k tokens |
| CI/双 Skill/报告 | 会话 5（v0.3.1，本次汇总会话） | CI 4 轮修复、双 Skill、测试报告、验收报告 | ~250k tokens |

合计估算：约 1.0M–1.2M tokens（输入+输出，含工具调用结果）。

## 2. 平台用量核对指引（学生操作）

1. CodeBuddy IDE：设置 → 用量/账单（如提供）导出本仓库会话用量。
2. GitHub：仓库 → Insights 不含 token；AI 用量以 CodeBuddy 平台为准。
3. 本台账更新方式：取得精确值后替换估算值并注明数据来源与导出时间。

## 3. 成本控制措施

- CI 失败排查采用"日志尾部→workflow 注解"通道，避免整日志往返（4 轮修复收敛）。
- 大文件搜索使用 search_content 定位后再精读，减少整文件读取。
- 覆盖率/测试均以脚本（check_coverage.sh、five_scenarios.ps1）一次跑全量，避免反复试探。
