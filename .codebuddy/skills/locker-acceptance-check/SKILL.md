# Smart-Locker 验收检查

本 Skill 用于对 Smart-Locker 最终版本做交付前验收。验收 Agent 为只读角色：不得修改业务代码，只可运行测试、调用接口、执行前端 e2e 与截图。产出《项目验收报告》（逐项结论 + 证据位置），报告存 `docs/验收报告.md`。

## 验收依据（必须先读，不得只依据开发声明）

1. `docs/智能寄存柜-需求文档.txt` —— 原始需求，逐项列出功能点。
2. `AGENTS.md` —— AI 约束：覆盖率 ≥85%、计费口径、Git 提交规范、假设清单。
3. `docs/任务清单.md`、`docs/假设清单.md`、`docs/测试报告.md`（若存在）。
4. 独立会话执行验收；核对代码版本 = 待验收版本（`git log --oneline -5`）。

## 验收步骤

### 1. 环境与部署冒烟
- 本地 MySQL `smart_locker` 库可连，迁移启动自动执行，重启后业务数据可查。
- 后端 `cmd/server` 启动于 ：8090，`GET /api/cities` 返回 200。
- 前端静态服务可访问 `/#u-home`。Docker 部署已按假设清单豁免，以 GitHub Actions 质量门禁 + 本地启动冒烟记录代替（报告须注明）。

### 2. 质量门禁复跑（独立证据，不采信开发声明）
- `bash scripts/check_coverage.sh 85` → 整体 ≥85%，核心包（订单/计费/优惠券/权限/客服）分别 ≥85%。
- `go test -race -count=1 ./...` 全绿。
- GitHub Actions CI 最近一次运行状态为 success（unknown 须标注并说明）。

### 3. 五大演示场景（HTTP 实测或 `node scripts/e2e_check.js`，截图存 `shots/`）
1. 正常成交：登录→选网点/柜型→试算（预付=1小时+押金）→模拟支付→下单占格→取件码开柜→关门结算（多退少补正确）。
2. 免费时长：存入后 10 分钟内取件 → 全额退款，订单结束。
3. 上报异常：订单上报柜格异常 → 柜格置 fault、订单结束并全额退款、告警生成。
4. 权限越权：site_admin 访问非授权网点接口 → 403；service 访问管理模块 → 403；未登录访问用户接口 → 401。
5. 优惠券结算：使用 8 折/1 小时/1 元券结束订单，优惠不超过订单金额，应付 ≥0。

### 4. 硬错误核查（任一命中即验收不通过）
- 超卖：并发下单分配同一柜格。
- 重复收款 / 重复退款 / 重复释放柜格。
- 越权访问他人订单或管理接口。
- 计费口径与题面 8 条不一致（对照 locker-business-rules Skill 条目一）。
- 提交信息违反 `[类型] [版本] [#编号] 描述` 规范，或编号不存在于任务清单。
- 密钥/敏感数据入库。

### 5. 报告输出

《项目验收报告》结构：验收结论（通过/有条件通过/不通过）｜逐项需求结论表（需求条目→证据文件:行或接口响应→符合/不符合）｜五大场景记录｜覆盖率与 CI 证据｜缺陷清单（编号/定级/复现/责任方）｜假设与豁免说明（Docker 豁免、模拟实现）｜整改建议。所有结论必须有证据位置；无法执行的项标 unknown 并说明责任，禁止编造"已通过"。
